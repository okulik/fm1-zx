# More games for the built-in pack (Plan 4)

**Status:** approved by the owner, 2026-11-13. Extends the main design (`2026-11-11-zx48k-fm1-design.md`, §5.6
"Game pack") and replaces its dropped milestone 5 as the next plan.

## 1. Intent

The pack today is two test programs and one real game (Castaway). The owner wants the pack to
serve **both** of its audiences (the owner's answer, 2026-11-13: "both"):

- **the test bench**: games and programs that exercise the parts of the machine the design
  names as risky (screen updates, beeper timing, border, tape loading), so the emulator gates and
  later the hardware test cover them;
- **the public demo, later**: a picker with several games worth playing on the FM-1's controls,
  in the browser page and on the device.

## 2. Goals, non-goals, anti-goals

**Goals**
- Add five freely licensed games, chosen by the owner from a researched shortlist
  (the research report's facts are summarised in §4):
  1. **ZX Sopwith** (Neil Rackett, 2026, port of David L. Clark's Sopwith), side-scrolling
     biplane shooter, GPL-3.0-or-later.
  2. **Escape from Colony 8** (Juan J. Martínez, 2014), action platform shooter, MIT.
  3. **ZX Dino** (foxweb, 2026), endless runner after Chrome's offline dinosaur game, MIT.
  4. **A World of One-Way** (Serdjuk, 2021), sliding puzzle, Apache-2.0 with an MIT beeper engine.
  5. **The Legend of Traxtor** (Juan J. Martínez, 2014), puzzle action, MIT; **Micro INC** (same
     author, MIT) takes its place if Traxtor fails the gate or the playtest.
- Add two test programs of our own, generated like `scroll.sna` and `border.sna`, for the two
  test cases no freely licensed game covers:
  - **`tape.tap`, a multi-load tape**: autostarts with `LOAD ""`, and its code, once running,
    loads a further block from the tape through the ROM's LD-BYTES and shows it. This tests the
    LD-BYTES trap mid-game, which the design's loading section exists for ("so multi-load games
    work") and nothing in the pack exercises today.
  - **`tune.sna`, beeper music**: a fixed melody of distinct pitches played continuously for
    several seconds by a timed `OUT (0xFE)` loop. It tests sustained, changing-pitch beeper sound
    through the audio path (the border program tests one steady tone).
- Every game passes the **licence gate** (§3) and the **playtest gate** (§3) before it lands; a
  game that fails either is left out and the reason recorded in `LICENSING.md` under "Considered
  and left out".
- Each game gets a key map and a `demo` script in `games/games.toml`, so the existing per-game
  report (`fw_report`: frames per second per divider, "the demo got into play") covers it.
- Docs, licences and tests follow: `third_party/games/<id>/`, `LICENSING.md`, `REUSE.toml`,
  `LICENSES/` (Apache-2.0 is new), `docs/controls.md`, `docs/hardware-test.md`, `README.md`,
  `BUILDING.md`'s report numbers, the golden hashes and images, and the browser page's key maps
  (generated by `fmzx-pack keymaps`, so they follow the manifest).

**Non-goals**
- Games under a non-commercial licence (Cheman, Cheril of the Bosque) and games with uncleared
  parts (The Virus: a routine by Andy Dansby of unknown licence). Left out by the owner's
  decision, 2026-11-13.
- Outpost (Juan J. Martínez, 2026): its licence is unclear. Asking the author is the owner's
  call, outside this plan; it can join the pack later through the same gate.
- Publishing the browser page, USB game upload, the picker's look, the order beyond §5.
- Changes to the machine core to make a game work. If a game needs one, it fails the playtest
  gate here and the core change becomes its own decision.

**Anti-goals**
- A game in the pack whose licence or parts we cannot show are cleared, from the author's own
  words. One unclear part keeps the whole game out (the rule that dropped Star Field, Mars Base
  and Moon Caves).
- A modified game file. Every game is the author's file byte for byte, pinned by SHA-256.
- A game that sits in the picker but cannot be played on the FM-1's controls.

## 3. The gates

**Licence gate** (as in Plan 2, Task "games"): the evidence is the author's own licence file or
README in their repository or release. Copy that file (and the licence text it refers to) into
`third_party/games/<id>/`, quote the sentence in the game's `README.md` with the source URL,
download URL and SHA-256, and add the attribution to `LICENSING.md`. In addition, read the
game's credits and README for third-party parts (loading screen, music, graphics, font, bundled
libraries); each must be the author's own or carry a licence that permits redistribution. Known
points to settle at the gate:

- **ZX Sopwith**: the original Sopwith's licence (David L. Clark's GPL release) must allow the
  port's GPL-3.0-or-later; the release tag is rolling, so the file is pinned by its SHA-256 and the
  commit it was built from is recorded. Use the 48K `.sna` (49,179 bytes); the `.tap` is a single
  BASIC block and is not needed.
- **Colony 8, Traxtor (or Micro INC)**: the release zip's README says MIT, the usebox.net footer
  says CC BY-NC-SA 4.0 "unless stated otherwise". Treated as for Castaway: the release states
  otherwise, so the release's MIT applies; the README records both.
- **A World of One-Way**: Apache-2.0 for the game, MIT for the beeper engine (its notice kept).
  The font (`font.SpecCHR`) and the title screen must be shown to be the author's or cleared; if
  either is not, the game fails the gate. Apache-2.0 joins `LICENSES/` and `LICENSING.md`'s
  statement that nothing in the repository is under the Apache License is corrected.
- **ZX Dino**: MIT; its homage to Chrome's dinosaur game must use its own graphics (checked
  against the repository's credits).

**Loader check (first step of the playtest gate)**: before anything is committed, walk the
game's `.tap` blocks (flag, length, checksum) and confirm it loads through the standard ROM
loader that our core traps at LD-BYTES (0x0556): a BASIC loader and standard-speed blocks, no
turbo or custom loader. A game whose release only loads with a custom loader fails the gate. The
author's own `.sna` or `.z80` of the same release may be used instead of the `.tap` (as for ZX
Sopwith), byte for byte; converting a file ourselves, or a `.tzx` (the core does not read it),
is not allowed.

**Playtest gate**: in the host core (`zx-tests` `games.rs`: loads and runs, golden frame hash) and
in the firmware under fm1-emu (`fw_report`: its `demo` script gets past the title into play and
the screen keeps updating). The builder also plays each game in the browser page
(`tools/web-demo`) through its FM-1 key map: title, start, a minute of play, HOME and back. A game
that does not run correctly at 48K in our core fails the gate.

**Gate failures**: a game that fails a gate is dropped at once and recorded; nobody writes to an
author or waits during the plan (asking authors is the owner's, later). If Traxtor fails, Micro
INC is tried in its place. If games fail and fewer than five land, the plan ships the ones that
passed and reports which were dropped and why; it does not block.

## 5. Decisions

**The owner's**
- The set above, the two test programs, and the exclusions (2026-11-13).

**The builder's calls made here (the owner may overrule)**
- **Order in the picker**: unchanged at the top (`scroll`, `border`, `castaway`), new games after
  Castaway in the order of §2, the two new test programs last. The firmware and emu-gate tests
  pick games by index; keeping the first three in place keeps that churn small. The order for the
  public page is revisited with publishing.
- **Controls coverage**: every control a game needs to play (move, fire, jump, start, pause,
  and game actions such as Sopwith's bomb, flip and home) is mapped; options a player does not
  need on the FM-1 (key redefinition, sound toggles) may stay unmapped. The FM-1 has 27 notes
  (F3-G5) and 14 buttons, enough for every game here.
- **Key maps** follow Castaway's pattern (docs/controls.md): the left-hand notes F3-A3 are the
  directions, C5 and up fire, the remaining game keys on nearby notes, Kempston where a game
  offers it and the keys where that is simpler; each game's FM-1 map is documented in its
  `README.md` and in `games.toml`.
- **`tape.tap` behaviour** (exact code is the builder's): BASIC `LOAD ""CODE: RANDOMIZE USR`
  loader, a code block, then a headerless data block; the code waits a fixed number of frames,
  calls LD-BYTES for the data block into the screen bitmap, then halts in a loop. Tests: the host
  core shows the data block's pattern on screen after the load and the tape position is at its
  end; the firmware does the same under fm1-emu (screen golden).
- **`tune.sna` behaviour**: a short repeating melody (for example a C major scale, each note a
  fixed number of frames, interrupts left on), pitches chosen to land on whole T-state loop
  counts. Tests: the host beeper output and the firmware's audio under fm1-emu each show the
  melody's pitches in order within a tolerance the builder sets from the existing border-tone
  test, with no gap between notes. The firmware half extends `fw_audio`'s existing method (zero
  crossings over audio captured from fm1-emu) to one window per note; no new emu-gate
  machinery is expected.
- **Picker with ten games**: the pack header and the menu keep a 32-bit count and the menu
  scrolls (`top`), so no limit is expected; if the picker or the pack turns out to need a change
  for ten entries or a longer name, that change is in scope.
- **Budget**: the pack is 23,468 bytes now; five games of at most about 49 KB raw each fit many
  times over in the 488 KB left in the app slot. `fw_budget` keeps checking it.
